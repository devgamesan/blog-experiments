# VLM + Grounding DINO + SAM2 物体自動分類・カウント

カテゴリを事前指定せずに、静止画像の中にある物を見つけ、種類ごとに数えるJupyter Notebookです。最終件数をAIに直接答えさせず、画像上で見つけた「物がありそうな場所」を整理してからプログラムで数えます。

## このNotebookで使う言葉

専門用語はコードやモデル名として出てきますが、役割は次のとおりです。

| 言葉 | このNotebookでの意味 |
| --- | --- |
| VLM（以後「画像理解AI」） | 画像を見て「何が写っていそうか」を言葉で考えるAI。最初は探す物の名前を挙げ、後では迷いがある場所だけを確認する。最終個数は数えない。 |
| Grounding DINO（以後「場所探しAI」） | VLMが挙げた名前を手掛かりに、画像のどこにその物がありそうかを四角で探すAI。 |
| SAM2（以後「輪郭なぞりAI」） | 四角の中や画像全体から、物らしい形の輪郭をなぞるAI。 |
| 候補 | 「ここに何かありそう」と見つけた場所。まだ数えると決まった物ではない。 |
| 輪郭（mask） | 画像のどの部分をその候補の物とみなしたかを色で示した形。輪郭の数は物の数ではない。 |
| 追加確認 | 数えるか迷う候補だけをVLMに見てもらうこと。すべての候補は送らない。 |
| 自信度 | AIがどの程度確からしいと考えているかの目安。厳密な確率ではない。 |

## 処理の全体像

```text
入力画像
  │
  ├─ VLM: 数えられそうな物の名前と別名を挙げる
  ├─ 場所探しAI（Grounding DINO）: その名前の物がありそうな場所を四角で探す
  ├─ 輪郭なぞりAI（SAM2）: 四角から物の輪郭をなぞり、名前なしでも見つけ漏れを探す
  ├─ 候補を整理: 同じ物を二度見つけていないか、部品ではないかを調べる
  ├─ VLM: 迷いがある候補だけを追加で確認する
  └─ 集計: 部品・背景・画像内の絵を除き、名前ごとに数える
```

VLMは意味、Grounding DINOは場所、SAM2は形を担当します。この分担により、VLMが総数を直接推測したときに起こりやすい見逃しや二重計数を減らします。

最終表示では、英語の集計用名に日本語名を併記します。たとえば、集計やJSONの内部名が`mug`なら、画像のラベルと表では`mug（マグカップ）`と表示します。日本語名はVLMがカテゴリを発見するときと追加確認するときに取得します。取得できなかった場合は、誤った翻訳を補わず英語名だけを表示します。

第8節では、最終結果を種類ごとに集計した表を表示します。表には「数える（確度が高い）」「数える（やや不確か）」「要確認（数えない）」「最終的に数える個数」を表示します。最後の列が、種類ごとの報告件数です。

種類名は、空白・ハイフン・アンダースコアだけが異なる表記を同じ名称として扱います。たとえば`toy car`、`toy-car`、`toy_car`は、カテゴリ発見時に決めた1つの統一名へ戻してから集計するため、最終表に別々の行としては出しません。

## まず押さえる考え方

このNotebookで扱う「候補」は、まだ数えると決まった物ではありません。場所探しAIが見つけた四角、または輪郭なぞりAIが切り出した領域に、名前・形・確認結果を少しずつ足していく途中の情報です。

```text
候補                         最終的に数える物
四角だけ、または輪郭だけ       実際にあり、1個として扱える
名前が間違っているかもしれない  集計用の名前にそろっている
部品や背景も混ざることがある    同じ物との重複が整理されている
                             数えた・数えない理由が残っている
```

たとえばマグカップを探す場合、Grounding DINOは「mugらしい場所」に四角を描きます。SAM2はその四角から取っ手を含む形をなぞります。ほかの候補がその形とほぼ同じなら同じマグカップとして1つにし、小さな候補がマグカップの形の中に収まっていれば、取っ手などの部品かもしれないためVLMに確認します。つまり、**最初に見つかった四角の数ではなく、整理後に残った独立した物の数**を数えます。

uv run python -m ipykernel install --user \
  --name vlm-grounding-dino-sam2-counting \
  --display-name 'VLM + Grounding DINO + SAM2 Counting (Python 3.12)'

JupyterLabで`vlm_grounding_dino_sam2_counting.ipynb`を開き、`VLM + Grounding DINO + SAM2 Counting (Python 3.12)`カーネルを選択してください。

## API設定

APIキーをNotebookやGitへ書き込まず、環境変数またはこのディレクトリの`.env`へ設定します。`.env`は既存の環境変数を上書きしません。

```bash
cp .env.example .env
export VLM_API_KEY='your-api-key'
export VLM_MODEL='your-vision-model'
```

- `VLM_API_KEY`: API認証キー
- `VLM_MODEL`: 画像入力に対応するモデル名
- `VLM_BASE_URL`: OpenAI以外の互換APIを使う場合だけ指定する`/v1`を含むURL

NotebookはAPIキー、Base64画像、APIリクエスト本文を表示しません。

## 各モデルの役割と可視化

Notebookは各段階で候補数の変化を表で示し、元画像、検出ボックス、SAM2マスク、重複関係、追加確認が必要な候補、最終結果を順に可視化します。

| 段階 | 役割 | 主な可視化 |
| --- | --- | --- |
| VLMカテゴリ発見 | 数えられるカテゴリ・別名を列挙 | カテゴリ表、検出プロンプト |
| 場所探し | 名前ごとに「ありそうな場所」を探す | 名前付きの色付き四角、自信度の分布 |
| 輪郭なぞり | 四角を物の形へ近づけ、名前なしの候補も拾う | 色付き輪郭、形の自信度・面積の分布 |
| 候補の整理 | 同じ物を二度見つけていないか、部品ではないかを調べる | 候補どうしの重なり度表、候補一覧 |
| 追加確認 | 迷いがある候補だけをVLMで確認する | 対象の切り抜き、確認前後の比較 |
| 最終集計 | 数える候補を名前ごとに集計する | 最終の色付き画像、棒グラフ、JSON |

「形がどのくらい重なれば同じ物か」の初期値は0.65、「小さい形が大きい形にどのくらい収まれば部品の疑いを持つか」の初期値は0.85です（どちらも0〜1で、大きいほど条件が厳しくなります）。名前なしで見つかった輪郭のうち、既存候補と重ならないものは最大20件まで追加確認の対象にします。

### 可視化の読み方

| 表示 | 何を意味するか | 次に確認すること |
| --- | --- | --- |
| 色付きの四角 | 場所探しAIが名前に反応した領域 | 枠が物全体を覆っているか、同じ物に複数の枠がないか |
| 半透明の色 | 輪郭なぞりAIがその候補の物と考えた部分 | 部品・背景まで含んでいないか、隣り合う物を分けられているか |
| 候補どうしの重なり度表 | 行と列の候補が同じ場所を覆う割合。1はほぼ同じ、0は別の場所 | 対角線以外で高い値の組み合わせ |
| 追加確認が必要な候補ギャラリー | VLMへ送る候補 | なぜ追加確認が必要か |
| 最終の重ね合わせ画像 | 集計まで残った候補 | 数える候補・要確認の候補・名前未確定の候補の内訳 |

候補IDの色は処理全体で固定です。同じIDを異なる図で追うと、どの段階で統合・再分類・除外されたかを確認できます。

## 候補が最終件数になるまで

| 段階 | 判断する問い | 候補への影響 |
| --- | --- | --- |
| カテゴリ発見 | 何を探すべきか | 検出プロンプトを作る。この段階では数えない。 |
| 場所探し | その名前の物は画像のどこにありそうか | 四角の候補を追加する。見逃しを減らすため、物ではない場所も少し混ざる。 |
| 四角から作る輪郭 | 四角の中のどこまでが対象の物か | 物の形と、輪郭を取れた自信度を追加する。 |
| 名前なしで作る輪郭 | 名前を指定しなくても物らしい場所があるか | 名前未確定の候補を補う。 |
| 候補の整理 | 同じ物を複数回見つけていないか | 見つけた方法をまとめ、明らかな重複を減らす。 |
| 追加確認 | 実物・部品・背景・画像内の絵のどれか | 数えない・名前未確定・要確認にする理由を追加する。 |
| 最終整理・集計 | 独立した物として何個残ったか | 「数える」と判断した候補だけを件数に加える。 |

最初の検出数と最終件数が一致しないことは正常です。同一物体への重複枠と部品・背景・描画物体は減り、自動マスク由来の見逃し候補は増えることがあります。

## Grounding DINOの検索語を分ける理由

Grounding DINOには、画像とともに`mug. cardboard box. tennis ball.`のような文章形式の検索語を渡します。各語句は「画像のどこにその物体があるか」を探す手掛かりです。

VLMが`coffee mug`を見つけた場合、`label`の`coffee mug`、`canonical_label`の`mug`、`aliases`の`cup with handle`をすべて検索語にします。別名を併用すると検出漏れを減らせます。各検索語の検出結果はすべて`mug`へ対応付け、後段のマスク重複排除で同じ物体を統合します。ただし、すべてのカテゴリと別名を1つの非常に長い文章へ詰め込むと、次の問題が起きやすくなります。

- 検索語が長くなり、似た語の対応付けが曖昧になる
- モデルのテキスト入力長に近づき、語句が切り詰められる可能性がある
- どの語句の組で誤検出・見逃しが起きたかを追跡しにくい
- 画像と多数の語句を一度に処理するため、GPUメモリと待ち時間が増える

そのため、検索語を`LABELS_PER_BATCH`件ずつに分け、複数回の検出結果を後でまとめます。既定値の**20件はモデルの上限ではなく、精度・GPU負荷・可視化の分かりやすさのバランスを取るための運用上の初期値**です。

```text
カテゴリ発見結果
  mug: [coffee mug, cup with handle]
  box: [cardboard box]
  ball: [tennis ball]
          │
          ▼
検索語の列: coffee mug / cup with handle / mug / cardboard box / box / tennis ball / ball
          │
          ├─ 1〜20語: Grounding DINO実行 → 検出結果A
          ├─ 21〜40語: Grounding DINO実行 → 検出結果B
          └─ …
          │
          ▼
すべての検索結果を集計用の統一名へ戻し、同じ場所の重複を整理
```

候補カテゴリが少ない画像では1バッチだけ実行されます。カテゴリが多い、またはGPUに余裕がない場合は`LABELS_PER_BATCH`を10程度へ下げます。少数カテゴリで速度を優先する場合は上げられますが、まず20のまま検出結果を確認してください。

## SAM2で輪郭を作り、見つけ方を整理する

SAM2は物の名前を知りません。画像上の場所を手掛かりに「ここまでが同じまとまりの形らしい」と輪郭を作るAIです。このNotebookでは、次の2通りで使います。

| 使い方 | SAM2に渡すもの | 得られるもの | 目的 |
| --- | --- | --- | --- |
| 四角から輪郭を作る | 場所探しAIが描いた四角 | その四角の中の物らしい形 | 物の場所を四角より正確な形にする |
| 名前なしで輪郭を作る | 画像全体 | 名前に関係なく見つけた形 | 名前で探せなかった物を補う |

### 四角から輪郭を作る例

```text
Grounding DINO: "mug"らしい矩形
        ┌──────────────┐
        │  マグカップ  │  ← 矩形には背景や隣の物体も含まれ得る
        └──────────────┘
                    │ ボックスをSAM2へ渡す
                    ▼
SAM2: マグカップの輪郭マスク
        取っ手を含む画素だけを候補の形状として保持
```

輪郭を使うと、四角どうしを比べるより正確に「同じ物か」「一方が他方の部品かもしれないか」を比べられます。SAM2が返す形の自信度も、追加確認する候補を選ぶ参考にします。

### 名前なしで見つけた輪郭を、どう候補へ反映するか

名前なしで作る輪郭は便利ですが、物全体だけでなく、棚板、箱の一面、取っ手、影に近い切れ端まで拾うことがあります。そのため**輪郭の数を物の数としては数えません**。まず極端に小さい・大きい形と、自信度が低い形を除き、その後で既存の候補と見比べます。

最初の候補リストは、場所探しAIの四角から作った輪郭で始まります。名前なしで見つけた輪郭を、一つずつこの候補リストと見比べます。

```text
開始時の候補リスト
  obj-0001: 「mug」の四角から作った輪郭
  obj-0002: 「box」の四角から作った輪郭

SAM2が名前なしの輪郭を1件生成
  │
  ├─ obj-0001と十分重なる（形の重なりが0.50以上）
  │      → obj-0001のまま残す。新しい候補は作らない。
  │      → 「両方の方法で見つかった」と記録する。
  │
  └─ どの既存候補とも十分に重ならない
         → 新しい候補を1件だけ追加する（最大20件）。
         → まだ名前も、数えるかどうかも決まっていないため、VLMへ確認する。
```

具体例として、画像に青いマグカップ、テニスボール、棚板があるとします。

| 名前なしの輪郭が覆う領域 | 既存候補との関係 | 候補リストで行うこと | この時点で数えるか |
| --- | --- | --- | --- |
| 青いマグカップ | `obj-0001`のマグカップと重なる | `obj-0001`のまま、両方の方法で見つかったと記録 | 数えない。後段の最終集計を待つ。 |
| テニスボール | 既存候補と重ならない | 名前未確定の新規候補を追加し、VLMへ送る | 数えない。VLMの判定を待つ。 |
| 棚板 | 既存候補と重ならない | 名前未確定の新規候補を追加し、VLMへ送る | 数えない。背景なら後で除外する。 |

ここでいう「整理」は、**輪郭を合体させる処理でも、この時点で数えると決める処理でもありません**。名前なしで見つけた輪郭が既存候補と同じ物を指すとき、新しい候補を増やさず「どちらの探し方でも見つかった」と記録するだけです。この記録は、最終JSONで「どの方法で見つけたか」を後から確認するためのものです。この時点では自信度や件数を変えません。最終的な輪郭には、場所探しAIの四角から作ったものを使います。

## 迷いがある場所だけを追加で確認する理由

場所探しAIと輪郭なぞりAIだけで、すべての候補を安全に数えられるとは限りません。そこで「数えてよいか迷う場所」だけをVLMに確認します。AIへ送る画像は2枚です。

- 対象だけを明るくした全体画像: どの場所について質問しているかを示す
- 周りも含めた切り抜き: 単独の物か、別の物の一部かを見分ける

VLMには「実際にそこにある物か」「1個として数えられるか」「部品・背景・ポスターや画面の中の絵ではないか」「集計用の名前は何か」を答えてもらいます。すべての候補を送らず、下のような迷いがある候補だけを送るため、外部APIの利用回数とコストを抑えます。

回答が読み取れない形式で返ったときは、1回だけ同じ質問をやり直します。それでも失敗した候補を、黙って消したり推測で確定したりはしません。名前が分かっている候補は「要確認」、名前が分からない候補は「物体らしいが名前を決められない」として残します。

Notebookのこの段階では、VLMの進捗も表示します。カテゴリ発見で1回、追加確認で通常は候補1件につき1回呼び出します。JSONの再試行が必要な候補だけは、さらに1回呼び出します。表示する「通常の予定回数」「再試行を含む最大回数」「実際の呼び出し回数」により、処理の進み具合とAPI利用量を確認できます。

### どの候補がVLMへ送られるか

| 追加確認する理由 | 例 | VLMが確認すること |
| --- | --- | --- |
| 場所探しAIの自信が低い | 自信なさそうに見つけた箱 | 本当に物か、名前は合っているか |
| 輪郭をうまく取れていない | 形が不安定な候補 | 物全体か、切れ端か |
| 同じ場所に複数の名前がある | 同じ場所に`cup`と`mug` | 集計用の名前を何にそろえるか |
| 別の物の一部かもしれない | 車全体の中の車輪候補 | 1個の物か、部品か |
| 名前なしで見つかった領域 | 既存の候補と重ならない領域 | 数える物か、名前を付けられるか |

送信画像は、候補以外を暗くした画像と周りも含めた切り抜きです。前者は「何を判定しているか」、後者は「周囲との関係」をVLMへ伝えるために使います。

## 自信度と集計の決め方

追加確認していない候補の自信度は、場所探しAIを0.60、輪郭なぞりAIを0.40の重みで合わせます。VLMで確認した候補は、場所探しAIを0.35、輪郭なぞりAIを0.25、VLMを0.40の重みで合わせます。

| Notebookの表示 | 内部のJSON値 | 集計 |
| --- | --- | --- |
| 数える（確度が高い） | `confirmed`（0.90以上） | 集計する |
| 数える（やや不確か） | `probable`（0.70以上0.90未満） | 集計する |
| 数えずに要確認として残す | `uncertain`（0.40以上0.70未満） | 別枠で表示する |
| 数えない | `rejected`（0.40未満または除外判定） | 集計しない |

部品、背景、写真・ポスター・画面内に描かれた物は、デフォルトでは集計しません。`unknown`（物体らしいが名前を決められない）は画像とJSONには残しますが、名前ごとの件数には含めません。

### 自信度をどう解釈するか

この自信度は、厳密な「正解する確率」ではありません。Notebook内で候補を比べ、数える・要確認・数えないへ分けるための目安です。異なる画像や設定の数字を、そのまま比べる用途には使いません。

- `confirmed`: 複数のAIの結果が十分に一致した候補
- `probable`: 数えるが、隠れ方や自信度に少し不安がある候補
- `uncertain`: 物らしいが、数に入れるだけの根拠が足りない候補
- `unknown`: 物らしい場所はあるが、安定した名前を付けられない候補

最終JSONの`reported_count`はconfirmedとprobableの合計です。`uncertain_count`と`unknown_objects`を見ることで、整数の件数だけでは失われる不確実さを確認できます。

## 調整ポイントと制約

- 見逃しが多い場合は`BOX_THRESHOLD`と`TEXT_THRESHOLD`を下げます。誤検出が増えるため、VLM検証数も増える可能性があります。
- 自動マスクは物体全体だけでなく部品や背景断片も生成します。マスク数をそのまま個数には使いません。
- 大量候補の画像ではギャラリーを最大30件に制限しますが、集計表は全件を対象にします。
- GPUがあれば利用します。Grounding DINOとSAM2は逐次ロードしてVRAM使用量を抑え、GPUがなければCPUで動作します。
- 入力画像は`../assets/test1.png`です。モデル重みは初回実行時にHugging Faceから取得され、リポジトリには保存しません。

### 期待どおりの結果にならないとき

| 症状 | まず見る可視化 | 主な調整 |
| --- | --- | --- |
| 明らかな物体が見つからない | カテゴリ表、検出ボックス | VLMカテゴリ名・別名を確認し、検出閾値を下げる |
| 同じ物体が複数回数えられそう | 候補どうしの重なり度表、融合後重畳 | `MASK_IOU_THRESHOLD`を少し下げ、候補マスクを確認する |
| 部品まで数えられそう | 追加確認が必要な候補ギャラリー、VLM比較表 | `CONTAINMENT_THRESHOLD`を下げ、部品判定を確認する |
| 背景や棚が候補になる | 自動マスク重畳、品質・面積分布 | 最小面積・最大面積・自動マスク品質閾値を上げる |
| VLM呼び出しが多い | 追加確認が必要な候補の表 | 追加確認の各閾値を上げる、未対応自動マスク上限を下げる |
